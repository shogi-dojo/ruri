# Ruri 瑠璃

**Ruby-shaped scripting for Emacs.**

Ruri is a small, explicitly specified language with Ruby syntax that
compiles to ordinary Emacs Lisp, plus a thin Emacs package for compiling
and loading `.ruri` source files. It is named after 瑠璃 (lapis lazuli) —
the gemstone meaning and sound connect it to Ruby. Like a Gemfile or
Rakefile, a `.ruri` file is Ruby you can read; unlike Ruby, it is never
executed as Ruby. Ruby runtime compatibility, objects, and gems are out
of scope.

## Hello world

`examples/hello.ruri`:

```ruby
command :hello_buffer do
  interactive
  with_current_buffer("*scratch*") do
    insert("Hello from Ruby syntax!\n")
  end
end
```

Compiles to `examples/hello.el`:

```elisp
;;; -*- lexical-binding: t; -*-
;;; Generated by ruri 0.2.0 from examples/hello.ruri. DO NOT EDIT.

(defun hello-buffer ()
  (interactive)
  (with-current-buffer "*scratch*"
    (insert "Hello from Ruby syntax!\n")))
```

Generic Emacs functions use the explicit `el` namespace and may be nested:

```ruby
command :describe_buffer do
  interactive
  el.message("Current buffer: %s", el.buffer_name())
end
```

Function names convert from snake_case to kebab-case. Arguments may include
strings, integers, floats, `true`, `false`, `nil`, symbols, arrays, and nested
`el.*` calls. Ruby symbols become quoted Elisp symbols, arrays construct Emacs
vectors, and both `false` and `nil` become Elisp `nil`.

## Requirements

Verified with:

- Ruby 4.0.6 with the Prism parser gem (prism ~> 1.9)
- Bundler 4.0
- GNU Emacs 30.2 (lexical binding; batch mode used for tests)

Distributed generated `.el` files run in any Emacs without Ruby.
Compiling `.ruri` source requires Ruby and the compiler dependencies.

## Install / development setup

From the project root:

```sh
bundle install
```

## Try it

```sh
bundle exec ruby bin/ruri compile examples/hello.ruri --output examples/hello.el
emacs -Q --batch -f batch-byte-compile examples/hello.el   # optional
```

In Emacs, load the package and run the command:

```elisp
(add-to-list 'load-path "/absolute/path/to/ruri/lisp")
(require 'ruri)
;; Development compiler configuration (when no `ruri` executable is
;; installed); use absolute paths and the correct Gemfile environment:
(with-eval-after-load 'ruri
  (setq ruri-compiler-executable "bundle"
        ruri-compiler-arguments
        '("exec" "ruby" "/absolute/path/to/ruri/bin/ruri" "compile")
        ruri-compiler-environment
        '("BUNDLE_GEMFILE=/absolute/path/to/ruri/Gemfile")))
```

Then:

1. `M-x ruri-load-file RET /absolute/path/to/ruri/examples/hello.ruri RET`
2. `M-x hello-buffer RET`
3. Switch to `*scratch*` — it contains `Hello from Ruby syntax!`

Expected behavior: the command inserts at the buffer's current point and
does not switch the selected window; repeated invocation inserts another
greeting at point.

`ruri-load-file` compiles first and only then loads the freshly generated
`.el` (never a stale `.elc`). `ruri-compile-file` only compiles, beside
the source, to `NAME.el`. On failure, compiler diagnostics
(`path:line:column: message`) surface in the error and nothing is loaded.

## Run the tests

```sh
bundle install
bundle exec ruby -Itest test/compiler_test.rb
bundle exec ruby bin/ruri compile examples/hello.ruri --output examples/hello.el
emacs -Q --batch -L lisp -l test/ruri-test.el -f ert-run-tests-batch-and-exit
emacs -Q --batch -f batch-byte-compile examples/hello.el
```

The Ruby suite covers exact output semantics, Unicode and escaping round
trips, syntax errors, unsupported constructs with source positions,
duplicate commands, and preserving previous output after a failure. The
ERT suite drives the real compiler, loads its output, and asserts
end-to-end behavior, including from a byte-compiled `.elc` in a fresh
batch Emacs.

## Language

The exact v0.2 contract — supported constructs, name rules, expression
semantics, and everything explicitly rejected — is
[`docs/language.md`](docs/language.md). Commands support `interactive`,
`with_current_buffer`, `insert`, and explicit `el.function_name(...)` calls.
Generic call arguments accept scalar literals, quoted symbol literals, vectors,
and nested `el.*` calls. Every rejection names the offending source position.

The compiler parses with Prism, validates the whole file, and serializes
validated internal forms; it never evaluates the input (no `eval`, no
`load`, no `instance_eval` — guarded by a static test). A structured
emitter escapes every string, so literal text can never become additional
Lisp forms.

## Compiler architecture

Compilation has four explicit stages:

```text
Prism AST → typed Ruri forms → generic Elisp AST → deterministic printer
```

The parser owns the Ruri language contract. The lowerer maps those language
forms to generic Lisp lists, symbols, strings, numbers, quotes, and vectors.
The printer knows only S-expression structure, escaping, and layout; it has no
special cases for `defun`, `insert`, or other Emacs forms. This keeps generated
output readable while giving future language constructs a single lowering
boundary.

## Status & limitations

This is an early vertical slice. Not supported (by design): locals,
conditionals, closures, block-taking generic calls, additional macros, string
interpolation, heredocs, nested commands, a custom major mode, file
watchers, byte-compile integration from the compiler, and everything else
listed in the contract's rejection section.
