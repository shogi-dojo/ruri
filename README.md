# Ruri 瑠璃

**Ruby-shaped scripting for Emacs.**

Ruri is a small, explicitly specified language with Ruby syntax that
compiles to ordinary Emacs Lisp, plus a thin Emacs package for compiling
and loading `.ruri` source files. It is named after 瑠璃 (lapis lazuli) —
the gemstone meaning and sound connect it to Ruby. Like a Gemfile or
Rakefile, a `.ruri` file is Ruby you can read; unlike Ruby, it is never
executed as Ruby. Ruby runtime compatibility, objects, and gems are out
of scope.

## Hello world

`examples/hello.ruri`:

```ruby
command :hello_buffer do
  interactive
  with_current_buffer("*scratch*") do
    insert("Hello from Ruby syntax!\n")
  end
end
```

Compiles to `examples/hello.el`:

```elisp
;;; -*- lexical-binding: t; -*-
;;; Generated by ruri 0.9.0 from examples/hello.ruri. DO NOT EDIT.

(defun hello-buffer ()
  (interactive)
  (with-current-buffer "*scratch*"
    (insert "Hello from Ruby syntax!\n")))
```

Generic Emacs functions use the explicit `el` namespace and may be nested:

```ruby
command :describe_buffer do
  interactive
  el.message("Current buffer: %s", el.buffer_name)
end
```

Function names convert from snake_case to kebab-case. Arguments may include
strings, integers, floats, `true`, `false`, `nil`, symbols, arrays, and nested
`el.*` calls. Ruby symbols become quoted Elisp symbols, arrays construct Emacs
vectors, and both `false` and `nil` become Elisp `nil`.

Commands also support hygienic lexical locals and Ruby conditionals:

```ruby
command :describe_buffer do
  interactive
  name = el.buffer_name
  if name
    el.message("Current buffer: %s", name)
  else
    el.message("No current buffer")
  end
end
```

`if`, `elsif`, `else`, and `unless` use Emacs Lisp truth semantics. Local
names are compiled with a private prefix, so a Ruby name cannot accidentally
bind an Emacs special variable.

Body-oriented Elisp forms use an ordinary Ruby block:

```ruby
command :prepend_marker do
  interactive
  el.save_excursion do
    el.goto_char(el.point_min)
    el.insert("START: ")
  end
end
```

This compiles to `(save-excursion …)` with the nested calls as its body. The
same mechanism works for other Emacs macros and special forms that take
trailing body forms; Ruri does not need a hardcoded catalogue of their names.

Callbacks use Ruby block parameters and capture command locals lexically:

```ruby
command :render_values do
  interactive
  prefix = "value="
  formatter = fn do |value|
    el.concat(prefix, value)
  end
  el.message("%s", el.mapconcat(formatter, ["a", "b"], ", "))
end
```

Named function values use `function(:identity)`, which emits
`(function identity)` and can be passed to hooks, timers, key bindings, and
higher-order Emacs functions.

Top-level noninteractive functions use the same Ruby block style. Required
block parameters become hygienic Elisp arguments, and the final expression is
the return value:

```ruby
function :factorial do |number|
  if number <= 1
    1
  else
    number * el.factorial(number - 1)
  end
end

function :decorate do |value|
  prefix = "Buffer: "
  el.concat(prefix, value)
end
```

Functions may call themselves or other definitions through `el.*`. A final
`if` or `unless` returns the value of its selected branch. Commands and
functions share one generated Elisp namespace, so duplicate names are rejected.

Zero-argument `el.*` calls use idiomatic Ruby without parentheses, such as
`el.buffer_name`. The compiler also accepts `el.buffer_name()` for
compatibility; both forms generate `(buffer-name)`.

Lisp data keeps Ruby arrays as vectors and uses explicit list forms:

```ruby
tail = list("b", "c")
pair = quote(cons(:key, :value))
template = quasiquote(
  list(:head, unquote(el.upcase("x")), splice(tail))
)
```

These compile to an evaluated list, the literal dotted pair `'(key . value)`,
and a template like `` `(head ,(upcase "x") ,@tail) ``. Plain `quote` accepts
only data, while `unquote` deliberately re-enters the evaluated expression
language.

Ruby operators and loops lower to ordinary Elisp control forms:

```ruby
count = 0
total = 0

while count < 3
  total = total + count
  count = count + 1
end

list(1, 2, 3).each do |item|
  total = total + item
end
```

Ruri supports short-circuit `&&` and `||`, `!`, general equality, numeric
comparisons, arithmetic, `while`, `until`, and `.each`. Arithmetic uses Emacs
numeric semantics; string concatenation remains `el.concat(...)`.

## Requirements

Verified with:

- Ruby 4.0.6 with the Prism parser gem (prism ~> 1.9)
- Bundler 4.0
- GNU Emacs 30.2 (lexical binding; batch mode used for tests)

Distributed generated `.el` files run in any Emacs without Ruby.
Compiling `.ruri` source requires Ruby and the compiler dependencies.

## Install / development setup

From the project root:

```sh
bundle install
```

## Try it

```sh
bundle exec ruby bin/ruri compile examples/hello.ruri --output examples/hello.el
emacs -Q --batch -f batch-byte-compile examples/hello.el   # optional
```

In Emacs, load the package and run the command:

```elisp
(add-to-list 'load-path "/absolute/path/to/ruri/lisp")
(require 'ruri)
;; Development compiler configuration (when no `ruri` executable is
;; installed); use absolute paths and the correct Gemfile environment:
(with-eval-after-load 'ruri
  (setq ruri-compiler-executable "bundle"
        ruri-compiler-arguments
        '("exec" "ruby" "/absolute/path/to/ruri/bin/ruri" "compile")
        ruri-compiler-environment
        '("BUNDLE_GEMFILE=/absolute/path/to/ruri/Gemfile")))
```

Then:

1. `M-x ruri-load-file RET /absolute/path/to/ruri/examples/hello.ruri RET`
2. `M-x hello-buffer RET`
3. Switch to `*scratch*` — it contains `Hello from Ruby syntax!`

Expected behavior: the command inserts at the buffer's current point and
does not switch the selected window; repeated invocation inserts another
greeting at point.

`ruri-load-file` compiles first and only then loads the freshly generated
`.el` (never a stale `.elc`). `ruri-compile-file` only compiles, beside
the source, to `NAME.el`. On failure, compiler diagnostics
(`path:line:column: message`) surface in the error and nothing is loaded.

## Run the tests

```sh
bundle install
bundle exec ruby -Itest test/compiler_test.rb
bundle exec ruby bin/ruri compile examples/hello.ruri --output examples/hello.el
emacs -Q --batch -L lisp -l test/ruri-test.el -f ert-run-tests-batch-and-exit
emacs -Q --batch -f batch-byte-compile examples/hello.el
```

The Ruby suite covers exact output semantics, Unicode and escaping round
trips, syntax errors, unsupported constructs with source positions,
duplicate definitions, and preserving previous output after a failure. The
ERT suite drives the real compiler, loads its output, and asserts
end-to-end behavior, including from a byte-compiled `.elc` in a fresh
batch Emacs.

## Language

The exact v0.9 contract — supported constructs, name rules, expression
semantics, and everything explicitly rejected — is
[`docs/language.md`](docs/language.md). Top-level definitions include commands,
noninteractive functions with required parameters and value returns, and
package structure: `variable`, `constant`, `custom` (with `type:`),
`require`, and `provide`. Definitions accept documentation strings via a
leading `doc "..."` statement. Commands support `interactive`,
`with_current_buffer`, `insert`, lexical locals, conditionals, and explicit
`el.function_name(...)` calls with optional body blocks, lexical `fn` values,
and named `function(:name)` references. Expressions include lists, cons cells,
literal quote, quasiquote with unquote and splicing, Ruby operators, loops,
and `var :name` reads of dynamic Emacs Lisp variables. Every rejection names
the offending source position.

The compiler parses with Prism, validates the whole file, and serializes
validated internal forms; it never evaluates the input (no `eval`, no
`load`, no `instance_eval` — guarded by a static test). A structured
emitter escapes every string, so literal text can never become additional
Lisp forms.

## Byte-identical conversion

`examples/greet.ruri` is a basic elisp package (`test/fixtures/greet.el`)
written in Ruri. Compiling it produces code that is **byte-identical** to
the hand-written file — every defvar, defconst, defcustom (with docstring
and `:type`), defun with docstring, require/provide, and call matches the
conventional layout a human writes:

```sh
bundle exec ruby bin/ruri compile examples/greet.ruri --output examples/greet.el
```

The only bytes that differ are comment lines: the package header/footer
comments are not expressible in the language, and generated files carry
Ruri's own provenance header. `test/byte_identity_test.rb` asserts the
byte equality after dropping comment-only lines from both files.

## Converting real packages

Beyond the byte-identical `greet` demo, `examples/org-fragtog.ruri` is a
semantic conversion of [org-fragtog](https://github.com/io12/org-fragtog)
(MIT/X11, original preserved in `test/fixtures/`) — a real MELPA package
with minor-mode state, buffer-local variables, hooks, timers, and org
element access. The conversion loads and runs in Emacs.

What the conversion needed that greet did not: `variable_local` for
`defvar-local` state, `assign` for `setq` on dynamic variables,
`keyword :begin` for self-quoting keyword symbols, and multi-keyword
`custom` (`group:`, `type:`, `options:`). Remaining structural deviations
are documented at the top of the converted file: `define-minor-mode` is
emulated as a variable plus toggle function, `&optional` parameters are
split into separate functions, `let*` becomes sequential locals with
hygienic names, and comments are not carried over.

## Compiler architecture

Compilation has four explicit stages:

```text
Prism AST → typed Ruri forms → generic Elisp AST → deterministic printer
```

The parser owns the Ruri language contract. The lowerer maps those language
forms to generic Lisp lists, dotted pairs, symbols, strings, numbers, reader
prefix forms, and vectors.
The printer knows only S-expression structure, escaping, and layout; it has no
special cases for `defun`, `insert`, or other Emacs forms. This keeps generated
output readable while giving future language constructs a single lowering
boundary.

## Status & limitations

This is an early vertical slice. Not supported (by design): optional and rest
function or lambda parameters, command parameters and interactive specs, nested
quasiquotation, loop exits, string interpolation, heredocs, nested commands,
a custom major mode, file watchers, byte-compile integration from the
compiler, and everything else listed in the contract's rejection section.
